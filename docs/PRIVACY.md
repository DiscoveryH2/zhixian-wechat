# 隐私与数据流

知弦 PC 在本机读取聊天文字，把需要分析的文本发送到你配置的模型 API。本页说明哪些内容会离开电脑、哪些文件会留下，以及这些边界的限制。

## 什么时候会访问网络

| 操作 | 目的地 | 发送或读取的内容 |
| --- | --- | --- |
| 打开正常界面、运行演示模式 | 界面和 OCR 使用本地资源 | 不需要上传聊天或截图 |
| 点击“测试连接” | 已配置的判断服务；有生成配置时也访问生成服务 | 内置测试文字、模型名和鉴权信息，不读取真实聊天 |
| 手动分析或自动分析 | 已配置的 Jev 判断服务和回复生成服务 | 选定范围内的消息、发言方向、关系、回复风格、匹配的背景资料；候选排序还会提交生成的候选 |
| 刷新消息来源 | 配置的本机 WeFlow `/health` | 仅健康检查，不读取聊天记录 |
| 选用 WeFlow 并开始读取 | 本机 WeFlow HTTP / SSE | 会话和消息；需要该服务的 API Token |
| 点击外部链接 | 用户选择的网页或服务 | 由系统浏览器和目标网站处理 |

默认自动分析已开启，但普通启动不会直接开始观察。点击“开始观察”后，符合触发条件的新消息会进入分析流程；需要逐次控制时，可以关闭自动分析，改为手动分析。

**本地读取与云端分析是两件事。** 默认 OpenRouter 配置会使用同一把 Key 调用 Jev 和回复模型，但它们仍是独立请求；数据也可能经过服务商选择的模型提供方。请查阅相应服务商的数据保留、训练使用和日志政策。知弦无法控制这些外部服务的存储行为。

远程模型地址必须使用 HTTPS，本机 loopback 可以使用 HTTP。请求不自动跟随重定向。独立回复服务与判断服务不属于同一来源时，不会自动转发判断服务的 Key；需要另行配置。

## 截图与 OCR

窗口画面由 Windows Graphics Capture 获取，再在本机执行 OCR。正常采集的截图只在进程内存中使用，不写入聊天截图文件，也不会作为图片上传给模型。

程序只能读取可采集窗口内的文字。显示名称、发言方向、消息正文和群聊发言人仍可能被 OCR 识别错误；这些文字错误也可能进入模型上下文。截图不上传，并不意味着识别得到的文字不会上传。

程序的 `--screenshot` 预览参数只允许与 `--demo` 一起使用。公开文档中的截图应始终使用这类合成演示数据。

## 本地文件

默认数据目录为 `data/`：便携版放在可执行文件旁，源码版放在仓库根目录。开发时可以通过 `--data-dir` 使用独立目录。

| 文件 | 内容 | 保护方式 |
| --- | --- | --- |
| `credentials.json` | API Key、独立回复 Key、WeFlow Token | Windows DPAPI 密文 |
| `config.json` | 服务地址、模型、界面与分析设置 | 明文 JSON，不包含上述 Key 原值 |
| `knowledge.json` | 笔记、标签、联系人、别名、关系和备注 | 明文 JSON |
| `history.json` | 开启历史保存后的会话和消息 | 明文 JSON；默认不创建 |

密钥只由后端保管；界面通过“是否已配置”状态确认是否保存，不读取已保存的 Key 原值。首次输入的 Key 仍会经过本地界面传给后端。

DPAPI 使用当前 Windows 用户环境保护密钥，复制文件到其他账户或电脑后通常需要重新填写。它不保证能抵御已控制当前账户的恶意程序，也不加密整个数据目录。**不要因为密钥文件是密文，就把数据目录公开。**

## 笔记、联系人和历史如何参与分析

分析会使用设置中的近期消息条数，并附上匹配到的背景：

- 联系人名称或别名匹配后，关系与备注可以进入上下文。
- 常驻笔记会作为背景；其他笔记根据标题、标签和近期对话匹配。
- 开启保存的历史可以在后续使用中恢复为会话上下文。

因此，笔记和联系人虽然保存在本机，**被选作分析背景的部分仍会发送到模型服务**。不要在笔记中放入无关密码、访问令牌或不应共享的信息。

## 清理与退出

“清空历史”清理应用管理的会话历史；关闭历史保存会删除已有 `history.json`，不会同时删除笔记、联系人或密钥。退出应用后可以删除整个 `data/`，清除应用保存的配置、密钥、笔记、联系人和历史。

文件删除不是安全擦除，也不会清除系统备份、外部模型日志或已经复制的内容。通过“复制”或“填入”使用过的候选还可能保留在 Windows 剪贴板历史、设备同步或其他剪贴板管理器中。

## 填入与发送

填入前会重新获取画面并核验会话标题、微信窗口及焦点。目标不一致、识别失败、画面过期或候选已失效时会拒绝填入。通过核验后，仅将文字粘贴到输入框；发送始终由用户操作。

这种核验不能证明同名联系人一定是同一个人，也不能消除窗口变化、OCR 错误等所有情况。请核对收件人和输入框内容后再发送。

## 反馈问题

请使用合成对话复现问题，附上版本、现象和不含隐私的日志摘要，不上传真实聊天截图、数据目录或 API Key。涉及泄露、越权读取或错误目标回填的问题，请按 [SECURITY.md](../SECURITY.md) 私下报告。
