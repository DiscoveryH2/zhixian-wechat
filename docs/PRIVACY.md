# 隐私与数据流

知弦 PC v1.5.0 可以只读访问已配置账号的本机微信数据库，也可以读取可见聊天文字、用户主动导入的归档和已启用的 WeFlow 数据源。文字分析会使用配置的模型 API；显式图片理解或联网语音转写还可能发送选定媒体。本页说明数据何时出网、哪些文件会留下，以及这些边界的限制。

## 什么时候会访问网络

| 操作 | 目的地 | 发送或读取的内容 |
| --- | --- | --- |
| 显示界面、执行窗口 OCR | 本地界面资源与 OCR 引擎 | 不需要上传窗口截图；已启用的数据源可能另行预热摘要 |
| 选择“本机微信数据库”并浏览或观察 | 当前 Windows 用户的 CipherTalk 配置与微信加密数据库 | 只在本机读取已配置账号的路径、密钥、会话索引及按需消息页；使用 SQLCipher 只读连接，不创建明文镜像 |
| 运行演示模式 | 本地合成演示数据 | 不使用真实聊天作为演示内容 |
| 点击“测试连接” | 已配置的判断服务；有生成配置时也访问生成服务 | 内置测试文字、模型名和鉴权信息，不读取真实聊天 |
| 手动分析或自动分析 | 已配置的 Jev 判断服务和回复生成服务 | 选定范围内的消息、发言方向、关系、回复风格、匹配的背景资料；候选排序还会提交生成的候选 |
| 可选自动回复 | 已配置的 Jev 判断服务和回复生成服务 | 当前白名单会话的新来信及本次生成所需上下文；不使用笔记作为自动草稿背景。模型服务的数据处理规则仍适用 |
| 刷新消息来源 | 配置的本机 WeFlow `/health` | 仅健康检查，不读取聊天记录 |
| 启用 WeFlow 后预热、浏览或观察 | 本机 WeFlow HTTP / SSE | 按操作读取会话、少量摘要、消息页或朋友圈；需要该服务的 API Token |
| 主动导入 ChatLab | 用户选择的本机文件和应用数据目录 | 读取导出记录并写入本机 SQLite 索引，不因导入就提交模型 |
| 预览图片或播放可用语音 | 所选导出目录、用户文件或允许的 WeFlow 本机媒体端点 | 按需读取真实文件；预览本身不需要调用模型 |
| 显式图片理解、联网语音转写 | 配置的视觉或转写服务 | 所选图片/音频字节、相应提示和模型配置；服务能力检查还可能访问公开模型元数据 |
| 本地语音转写 | 用户已准备的本地引擎和离线模型 | 本地处理音频；随后使用转写文字进行 AI 分析时，文本仍可能出网 |
| 朋友圈分析 | 配置的 Jev 和生成服务；使用配图时可能访问视觉服务 | 当前动态、选定关系和可用聊天背景；有可读取配图时可能处理首张图片 |
| 选择界面背景 | 本机图片和应用数据目录 | 缩放后保存为 `background.jpg`，只用于界面显示，不作为模型背景 |
| 点击外部链接 | 用户选择的网页或服务 | 由系统浏览器和目标网站处理 |

默认自动分析已开启，但普通启动不会直接开始观察。点击“开始观察”后，符合触发条件的新消息会进入分析流程；需要逐次控制时，可以关闭自动分析，改为手动分析。

**自动回复与自动分析是不同开关。** 自动回复默认在每次启动时关闭；必须明确启用并配置白名单。配置保存在本机明文 `data/auto-reply.json`，其中的会话 ID 属于私有信息。白名单内的新来信会先触发独立的回复时机判断，通过后才生成候选；文本和所需分析上下文会发送给已配置模型服务。自动回复的运行限制见[1.5.0 发行说明](releases/1.5.0.md)。

1.4.2 起，新来信会先请求 Jev 独立判断「现在是否值得回复」。判断为需要回复后，才继续起草与发送核验；“下一条是否要包含实质内容”不再被当作发送时机。发送过程的脱敏审计留在本机，详见下表。

1.4.0 预览增加单次、用户主动发起的历史补回复。只读取用户明确选中的、当前可见且在白名单内的会话，并根据上下文寻找最近一个尚未回应的来信回合；最多发送一条。已知时间戳超过 7 天的来信跳过。时间戳未知时，必须由用户明确确认当前会话仍需回应，并且 Jev 需要给出更强的把握。群聊只在可靠确认消息是定向发给当前用户或明确提及其群内显示名称时考虑回复；普通群聊讨论不会触发。功能不会广播或切换到屏幕外会话。进入发送前会再次请求 Jev 分析并通过风险和候选排序门控；消息仍会发送至配置的模型服务。发送受固定披露后缀、现有输入框核验、冷却/限额与一次性去重约束，失败时不自动重试。细节及验证状态见[1.4.0 发行说明](releases/1.4.0.md)。

**本地读取与云端分析是两件事。** 默认 OpenRouter 配置会使用同一把 Key 调用 Jev 和回复模型，但它们仍是独立请求；数据也可能经过服务商选择的模型提供方。请查阅相应服务商的数据保留、训练使用和日志政策。知弦无法控制这些外部服务的存储行为。

“识别图片”“转写语音”和选择文件进行处理是显式媒体操作，不是纯本地预览的同义词。使用联网模式时，这些操作会提交选定媒体；仅打开会话不会批量识别所有媒体。没有真实文件、只有类型标签时，不会生成替代的图像描述或转写。TTS 朗读和声音复刻尚未实现。

远程模型地址必须使用 HTTPS，本机 loopback 可以使用 HTTP。请求不自动跟随重定向。独立回复或媒体服务与判断服务不属于同一来源时，不会自动转发判断服务的 Key；需要另行配置。

WeFlow 只允许本机 loopback。媒体请求必须来自应用已签发的资产引用并通过地址检查；程序不自动抓取聊天、导出或朋友圈中出现的任意远程 URL，也不调用朋友圈的通用远程媒体代理来绕过这一边界。零散的 `sns_cache` 图片/视频不能恢复可靠的帖子作者、正文或评论，因此不自动当作朋友圈导入。

## 截图与 OCR

数据库模式不使用截图识别聊天记录。仅在要向当前可见微信会话发送时，知弦临时采集窗口画面并裁切会话标题和输入框区域做目标与草稿核验；聊天正文、群聊发言人与最近消息都来自数据库。这些画面仍只在内存中处理。无法核验唯一会话标题时拒绝发送。

窗口画面由 Windows Graphics Capture 获取，再在本机执行 OCR。正常采集的截图只在进程内存中使用，不写入聊天截图文件，也不自动作为图片上传给模型。这一规则适用于窗口 OCR；用户另行选择文件做图片理解属于上文所述的媒体操作。

程序只能读取可采集窗口内的文字。显示名称、发言方向、消息正文和群聊发言人仍可能被 OCR 识别错误；这些文字错误也可能进入模型上下文。截图不上传，并不意味着识别得到的文字不会上传。

自动回复还会在本机 OCR 微信左侧当前选中会话的最新摘要和时间，与右侧聊天尾部核对；该额外截图区域同样不落盘。摘要截断、短文本或时间/发言人识别不稳时可能跳过回复。

程序的 `--screenshot` 预览参数只允许与 `--demo` 一起使用。公开文档中的截图应始终使用这类合成演示数据。

## 本地文件

默认数据目录为 `data/`：便携版放在可执行文件旁，源码版放在仓库根目录。开发时可以通过 `--data-dir` 使用独立目录。

| 文件 | 内容 | 保护方式 |
| --- | --- | --- |
| `credentials.json` | API Key、独立回复/媒体 Key、WeFlow Token | Windows DPAPI 密文 |
| `config.json` | 服务地址、模型、界面与分析设置 | 明文 JSON，不包含上述 Key 原值 |
| `knowledge.json` | 笔记、标签、联系人、别名、关系和备注 | 明文 JSON |
| `history.json` | 开启实时历史保存后的会话和消息 | 明文 JSON；默认不创建 |
| `chatlab-index.sqlite3` | 主动导入的会话、消息、来源目录和媒体相对路径 | 明文 SQLite；不受实时历史开关控制 |
| SQLite 的 `-wal` / `-shm` 辅助文件 | 数据库运行所需的日志或共享状态 | 同样按私有数据处理，不应公开 |
| `background.jpg` | 用户选作界面背景的图片副本 | 本机明文 JPEG；与原文件分别存在 |
| `auto-reply.json` | 自动回复策略、白名单会话标题与 ID、去重状态 | 本机明文 JSON；默认不自动启用，不含聊天正文或回复草稿 |
| `send-audit.jsonl` | 发送键调用前后和核验结果的时间、进程 ID、本次运行随机目标编号与阶段 | 本机明文 JSONL；不含联系人/群名、聊天正文、候选或密钥；不进入发行包 |

本机数据库模式另外读取 `%APPDATA%/ciphertalk/ciphertalk-config.db` 和该配置指向的微信原始加密数据库。CipherTalk 配置库包含数据库密钥，本身也是敏感文件，不要上传或公开。知弦只在内存中使用该密钥，不复制到 `data/` 或上传模型，也不调用其闭源 DLL。微信数据库原件及 WAL 仍由微信保管，知弦以只读方式连接。

导入的原始 JSON / JSONL 和媒体文件仍在用户选择的位置。媒体预览、识别或转写结果还可能暂存在应用内存中；若其文字被加入会话并启用了实时历史保存，文字结果也可能随该会话持久保存。媒体原件和索引均不因密钥使用 DPAPI 就获得加密。

密钥只由后端保管；界面通过“是否已配置”状态确认是否保存，不读取已保存的 Key 原值。首次输入的 Key 仍会经过本地界面传给后端。

DPAPI 使用当前 Windows 用户环境保护密钥，复制文件到其他账户或电脑后通常需要重新填写。它不保证能抵御已控制当前账户的恶意程序，也不加密整个数据目录。**不要因为密钥文件是密文，就把数据目录公开。**

## 笔记、联系人和历史如何参与分析

分析会使用设置中的近期消息条数，并附上匹配到的背景：

- 联系人名称或别名匹配后，关系与备注可以进入上下文。
- 常驻笔记会作为背景；其他笔记根据标题、标签和近期对话匹配。
- 开启保存的历史可以在后续使用中恢复为会话上下文。
- 主动选择的微信数据库、导入会话或 WeFlow 消息页可以成为分析上下文；建立会话目录不等于把整库上传。
- 图片描述或语音转写被加入会话后，也可能作为后续文字分析的一部分发送。

因此，笔记和联系人虽然保存在本机，**被选作分析背景的部分仍会发送到模型服务**。不要在笔记中放入无关密码、访问令牌或不应共享的信息。

朋友圈判断可以参考所选好友的聊天背景。公开评论草稿的生成步骤只接收动态、关系类别和写作风格，不接收私聊全文；Jev 的判断和排序步骤仍可能使用该背景。这个分离减少不必要的披露，但不能保证草稿不会出现不合适的信息，发布前仍需人工核对。

## 清理与退出

当前“清空历史”清理实时会话和相应历史状态；关闭实时历史保存会删除已有 `history.json`。**两者都不会删除主动导入的 SQLite 索引**，也不会删除笔记、联系人、密钥或原始导出文件。

需要清除导入归档时，先退出应用，再删除 `chatlab-index.sqlite3` 及其相应 SQLite 辅助文件。清除界面背景会删除应用的 `background.jpg` 副本，不删除原始图片。退出后删除整个 `data/` 可以清除该目录中保存的配置、密钥、笔记、联系人、实时历史、归档索引和背景副本；目录之外的导出和媒体须另行管理。

文件删除不是安全擦除，也不会清除系统备份、外部模型日志或已经复制的内容。通过“复制”或“填入”使用过的候选还可能保留在 Windows 剪贴板历史、设备同步或其他剪贴板管理器中。

## 填入与发送

手动填入前会重新获取画面并核验会话标题、微信窗口及焦点；手动填入只粘贴，发送由用户操作。可选自动回复会在发送前再次核验当前可见微信会话、最新来信、空且聚焦的输入框和填入后的草稿内容。数据库模式用稳定消息 ID 复核最新入站文字，并通过只裁切标题与输入框的画面核验目标，不解析截图中的聊天正文。已有草稿、验证失败或会话变化都会阻止发送；自动回复仅限白名单中的新收到纯文字消息，群聊默认要求可靠的提及确认。OCR 无法可靠判断群聊 @ 提及，需要用户明确启用全部群消息模式。

自动发送由知弦进程通过输入框按 Enter；微信焦点、界面状态或系统剪贴板变化仍可能影响结果。数据库模式会尝试在同一会话的数据库中确认新发出的消息；OCR 模式尝试用对应发出气泡和空输入框确认。这些都不能证明对方设备已收到；状态不确定时会暂停并要求检查。自动回复不切换到屏幕外会话，也不使用 WeFlow 发送 API；每条自动回复都会附加 `（以上内容为知弦生成）`。不要将按键成功视为送达证明。

这种核验不能证明同名联系人一定是同一个人，也不能消除窗口变化、OCR 错误等所有情况。请核对收件人和输入框内容后再发送。

## 反馈问题

请使用合成对话复现问题，附上版本、现象和不含隐私的日志摘要，不上传真实聊天截图、数据目录或 API Key。涉及泄露、越权读取或错误目标回填的问题，请按 [SECURITY.md](../SECURITY.md) 私下报告。
