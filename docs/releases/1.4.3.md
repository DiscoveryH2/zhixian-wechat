# 知弦 PC 1.4.3 预览版

本版修复真机群聊自动回复的一个阻断：长时间间隔后，微信把先前气泡滚出可见区；OCR 无法找到与上一屏的精确重叠，1.4.2 会保守暂停，连后续新消息也不再处理。1.4.3 只有在微信稳定处于后台，且左侧选中会话的最新摘要与右侧最后气泡、近期时间标记严格吻合时，才把当前可见消息重新设为基线。**这一批不发送**，只继续监听之后的新消息。每次后续自动判断以及发送前复核都再次要求最新摘要与聊天尾部匹配。如果摘要与聊天尾部失去对齐，会暂停自动回复；文字过短、近期同一发言重复内容或摘要截断会跳过这一轮。这样降低把用户手动翻看的旧记录当成新来信的风险。

自动发送仍由知弦进程完成：白名单内新来信先经过独立的 Jev「现在是否值得回复」判断，随后才进行风险分析、候选起草与排序；在当前可见的微信聊天里重新核验会话、最后来信、上一条上下文、空输入框及草稿内容，最后由知弦按发送键。每条自动回复附 `（以上内容为知弦生成）`。发送阶段的本机脱敏审计保存在 `data/send-audit.jsonl`。

## 验证状态

- 234 项本地 `unittest` 通过，另有 1 项环境性跳过；合成测试覆盖前台不确定视口仍暂停、后台视口有可靠尾部锚点才重建基线、旧批次不发送、下一条新来信继续进入判断，以及摘要/发言人/时间不符时拒绝发送。
- 真机上已确认一个测试群聊在旧版 1.4.2 因无重叠视口自动暂停，且未发生错误发送；本版针对这个观察到的失败路径修复。新包的独立自动发送仍以新的真机审计与发出气泡为准，不能把 Codex 人工点击发送算作验证。
- 窗口 OCR 只覆盖当前可见微信聊天，不会切换后台会话。群聊默认要求可靠 @ 我证据；若显式选择评估所有新消息，未直接指向用户时须满足更高的 Jev 置信度。模型判断不足、会话变化、已有草稿或无法确认发出时不会自动重试。
