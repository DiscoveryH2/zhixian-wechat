# 知弦 PC 1.4.2 预览版

这版重点是让自动回复由知弦进程完成，而不是只把草稿填进微信后依赖人工按发送。用户在自动回复页明确设置当前可见会话、会话类型、群聊范围和发送限额后，知弦仅对新收到的文字先做独立的 Jev「现在是否值得回复」判断；通过风险、置信度、候选排序与去重检查后，重新核验微信标题、最近来信、前一条上下文及输入框，再由知弦进程调用发送按键。每条自动回复固定附加 `（以上内容为知弦生成）`。

## 本版变化

- 发送期间新收到的消息合并为最新一轮，待当前发送结束后重新核验和判断；不会自动补发已经被上一条回复覆盖的消息。
- `data/send-audit.jsonl` 记录发送键调用前后及发出气泡核验状态。它只含时间、知弦进程 ID、本次运行随机目标编号与阶段，不含联系人或群名、聊天内容、候选回复或 API Key。该文件属于本机私有数据，不进入 Git 或发行包。
- 自动回复页强调「启动后自动判断并发送」，并把当前可见会话、来源、群聊规则与单次回复入口放在一起。
- 修复自动回复过去误用 Jev “下一条是否含实质内容”结果作为发送时机判断的问题；简短过渡回复也必须先通过独立的发送时机判断。
- 显式选择群聊「评估所有新消息」时，未直接 @ 用户的消息仍需 Jev 更高置信度。单次历史补回还必须有先前己方消息作为可核验边界；只考虑最新尚未解决的一轮，最多发送一条，不遍历群历史。

## 使用边界

自动回复每次启动默认关闭。OCR 只能处理当前可见的微信聊天，不能自动切换到后台会话；群聊默认仅考虑可靠的 @ 我证据。当前 OCR 不提供可靠 @ 标记，若要让知弦评估该群所有新消息，须显式选择相应群聊模式。普通群聊闲谈、已结束的话题、高风险或模型判断不足的消息应跳过。窗口、发言人、输入框或发送结果不确定时停止，不自动重试。

## 验证状态

- 225 项本地 `unittest` 通过，另有 1 项环境性跳过；覆盖 typed 回复时机、发送前安全门槛、忙时新消息续处理、进程内审计与群聊规则。
- 真实 Jev 接口使用合成群聊对话验证了「未解决问题→回复」与「话题已结束→跳过」，未发送真实聊天正文。
- 当前 Windows 微信中，知弦只读采集确认了指定群的会话标题和 4 条可见对方消息；暂停、恢复、停止均正常，不保存截图或正文。对群内现有最后一轮，Jev 单次判断选择跳过，因此尚无这一轮的真实群发送记录。
- 真实微信中的知弦进程独立发送需以 `data/send-audit.jsonl` 中 `enter_called`、`send_result=sent` 及微信对应发出气泡共同核对；不能把通过 UI 填入后由人或 Codex 点击发送算作自动发送验证。
