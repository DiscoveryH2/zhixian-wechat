# 数据、历史洞察与数字分身

1.8.0 是完整数据链路的技术预览。真实微信版本兼容、加密档案、商业授权取钥、签名与团队权限仍须单独完成验收。

## 数据取得方式与 CipherTalk 边界

参考用户 fork [DiscoveryH2/CipherTalk](https://github.com/DiscoveryH2/CipherTalk/tree/4b6df63eaf0aeeeec794b8f3284bc933a4c54fff)。该版本的 Windows 服务调用原生 DLL 从进程内存提取数据库密钥，并通过 contact.db 校验；macOS 服务调用 helper/dylib，包含断点捕获密钥、提权及 SIP 状态检查。它不是“给数据库换一个能读懂的哈希”。账号 ID 的哈希可以用于消息表命名，这与 SQLCipher 数据解密是两回事。

该 fork 的 [LICENSE](https://github.com/DiscoveryH2/CipherTalk/blob/4b6df63eaf0aeeeec794b8f3284bc933a4c54fff/LICENSE) 为 CC BY-NC-SA 4.0，明确限制商用。知弦没有复制这些服务、分身源码、内嵌签名材料或原生取钥组件。本轮独立实现的是公开格式和本地缓存结构的适配、身份索引、检索、分析及分身。现有 Windows 源仍读取用户已安装 CipherTalk 的配置来取得已有密钥，不是独立商业取钥方案。正式商业分发需要独立实现/经授权的连接器；仅 fork 仓库不能获得额外商业许可。

Windows 用户可从全局会话选择本机数据库记录，然后在「历史洞察 → 选择群聊 / 会话」建立只读快照索引。每批最多 500 条，界面持续分批请求直到读完，可以暂停；断点持久化，重新选择同一会话可继续。再次索引已完成会话会从最新记录重新开始，原始 ID 去重。Mac 使用 ChatLab 导入或兼容来源；原生取钥/发送仍不支持。索引明文存储在本机数据目录，原加密微信库不会修改。

## 联系人与群成员

导入 ChatLab 0.0.x JSON/JSONL，保留 members.platformId、accountName、发送者 sender、ownerId、platform。联系人唯一键是「平台、本人的稳定帐号、对方的稳定帐号」。只靠昵称不合并；群里的其它成员发言不会变成这个联系人的私聊或本人经历。

私聊信息如果没有唯一对方帐号，应重新导出可靠身份。旧 1.7 归档升级时从稳定 sender 回填成员；重新导入可补齐昵称。不同本人帐号的同一对方 ID 仍分开。原生库中未解析的帐号和未知发送者不会用于跨来源身份猜测。导出时清洗掉必要帐号 ID 会失去自动关联能力。

同一记录如果通过原生库和另一种导出格式都导入，跨格式消息 ID 可能不同；目前不宣称能消除这类重复。应选一种主要来源，并核对统计覆盖范围。

## 完整统计与有证据的洞察

「历史洞察」可选一个群聊/会话，或者一个联系人。前者计算该会话全部已索引消息；后者计算此人的私聊双方记录、共同群中此人本人发言、已索引朋友圈数量。展示消息量、发言分布、来源、时间范围、未知方向和未理解媒体。

完整统计在本机 SQLite 计算。点击生成后，模型取得最多 180 条跨时间分层的文字/已识别媒体样本，以及最多 100 条近期朋友圈文字，单条和总文字均受限制；不会上传整库。最多五条洞察，每条有观察、下一步和逐字匹配的来源引用。统计不等于模型逐条理解全历史；引用匹配也不能证明模型判断本身正确，需要用户核对。

语音转写/图片识别的归档结果持久化到独立解释表，不改原始消息。原文、类型或发送者发生变化时解释失效。解释明确标为可能有误，可用于洞察和分身抽样。完整原媒体依然必要；当前不包括全部 SILK/AMR 转码和任意加密图片解码。

## 朋友圈

两条输入途径：

- Windows「朋友圈 → 索引本机朋友圈文字」读取已有密钥可打开的 sns/sns.db 或 sns.db 中 SnsTimeLine(tid,user_name,content)，解析有界 XML。只有本机缓存文字，未知结构或未缓存内容可能缺失。
- 「导入朋友圈 JSON」先选择联系人，以此确定本人帐号和平台。接受帖子数组，或包含 items/timeline/posts 的对象。每条必须有稳定 id（或 snsId）、username；接受 text/contentDesc、timestamp/createTime、author/nickname。对象可声明 owner_id/ownerId 与 platform，必须与选定帐号一致。每个文件事务提交，重复 ID 更新；一个文件失败不会撤销先前成功的其它文件。

示例全部为合成内容：

```json
{
  "owner_id": "synthetic-self",
  "platform": "wechat",
  "items": [
    {"id": "synthetic-post-1", "username": "synthetic-friend", "nickname": "合成联系人", "contentDesc": "合成动态：计划完成", "createTime": 1700000000}
  ]
}
```

不根据昵称补作者，不下载帖子里的远程 URL。JSON 导入保存文字，外部媒体元数据不作为已识别图片。手动补充的动态也持久保存；绑定身份明确的私聊时能关联此人。已选好友的互动分析使用跨时间私聊/群本人发言样本把握语气，公开评论不能泄露私聊细节。点赞、评论建议由用户自行执行，不自动发布。

## 数字分身与运行时记忆

选择联系人后，可创建陪伴、纪念或沟通排练模式，并选择是否纳入共同群聊本人发言和朋友圈。初始最多 240 条时间分层聊天样本及 100 条近期朋友圈建立语气基底；只使用此人的原始话语，排除我的话和群里其它人的经历。

每次对话还会按问题从创建时完整索引边界内检索此人的原文字消息和全部已索引朋友圈，不限于初始抽样。命中来源保存为可管理的记忆副本；最终上下文最多 24 条来源、24,000 字以内和最近 6 轮有界模拟对话。关键词检索尚不是语义向量记忆；已识别媒体当前进入时间抽样，未建立媒体解释全文索引。新增导入记录可通过重新创建分身纳入。

界面始终标为 AI 模拟。系统 TTS 可以朗读生成文本，尚无语音复刻或视觉化身。模型根据历史表达创造对话，不声称是真人回归；新的生成对话只保存到模拟历史，不能变成原始事实。每次回复需逐字来源引用，展示在依据抽屉。

来源记忆可分页查看、定位原消息、停用和恢复。停用会清除该分身历史，防止旧生成回复重新带回被移除内容；被停用 ID 不参与全历史检索。所有当前记忆停用时阻止生成。删除分身会删除其记忆副本和模拟历史，保留原始档案。并发请求、记忆改动或分身删除使晚到结果失效，不保存过期回复。分身没有微信发送工具，已有自动回复是另一条受白名单约束的流程。

项目协作记忆是 [PROJECT_MEMORY.md](PROJECT_MEMORY.md)，由 [AGENTS.md](../AGENTS.md) 引导恢复任务；这是工程上下文，与联系人数据和分身运行时记忆分开。
